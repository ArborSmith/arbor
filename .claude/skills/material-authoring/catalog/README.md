# Setting up a MaterialCatalog for a project

The Arbor `material-authoring` skill is project-agnostic. The actual catalog (YAML entries, thumbnails, index) lives in the project, not the plugin, so it can travel via the project's Perforce stream and teammates share it.

## One-time bootstrap

Per project, create the catalog root. From inside the UE5 editor:

```python
import sys
sys.path.insert(0, "<plugin>/.claude/skills/material-authoring")
from extraction import _paths
_paths.bootstrap("<project>/MaterialCatalog", provenance="<project name>")
```

This creates:

```
<project>/MaterialCatalog/
  config.yaml              # sentinel + per-project settings
  vocabulary.md            # (you author this - controlled vocab for tags/traits)
  entries/                 # YAML entries (one per material)
  thumbnails/              # PNG thumbnails (one per material)
  _index.json              # generated index for the Slate widget
```

`config.yaml` settings:

| key | meaning |
|---|---|
| `default_vendor_dir` | content path for vendor-mode duplicates. Default `/Game/MaterialCatalog`. |
| `default_provenance` | string written into new entries' `provenance` field. |

## Path resolution

The Python tooling locates the catalog automatically:

1. `ARBOR_MATERIAL_CATALOG_ROOT` env var (explicit override)
2. `<project>/MaterialCatalog/` via `unreal.Paths.project_dir()` when inside UE5
3. Walk up from `cwd` looking for `MaterialCatalog/config.yaml`

If none resolve, `CatalogNotFoundError` is raised — bootstrap is required first.

## Extraction modes

`extract_material.extract(source_path, vendor=False)`:

- **Reference mode (default)**: the catalog YAML points at the source `/Game/...` path directly. No assets duplicated. Lightweight; relies on the team having the source in their Perforce stream. The default for materials that already live in the project.
- **Vendor mode (`vendor=True`)**: the source plus its non-engine MaterialFunction dependencies are duplicated into `<default_vendor_dir>/<id>/`, P4-added, and the YAML's `source` field rewrites to the catalog-owned copy. Use for style anchors you want to freeze, or materials migrated from external projects.

## What lives where

| In the plugin (git-tracked) | In the project (Perforce-tracked, NOT git) |
|---|---|
| `SKILL.md`, `scripts/`, `extraction/`, `references/` | `MaterialCatalog/entries/*.yaml` |
| Vocabulary template + this README | `MaterialCatalog/thumbnails/*.png` |
| Slate widget (Arbor C++) | `MaterialCatalog/_index.json` |
| C++ UFUNCTIONs (`UArborMaterialGraphTools`) | `MaterialCatalog/vocabulary.md` (project-tuned copy) |
| | Vendored assets at `/Game/MaterialCatalog/<id>/` |

## Entry shape

Each `entries/<id>.yaml`:

```yaml
id: brick_clay_old
source: "/Game/Assets/Materials/M_Brick_Clay_Old"
status: ok                     # ok | needs_review | bad | deprecated | broken
shading_model: MSM_DefaultLit
tags: [brick, clay, weathered, outdoor]
visual_traits: [dielectric, high_roughness, tiling_required, surface,
                pbr_realistic]
description: "Aged red clay brick..."
spec:
  path: "/Game/Assets/Materials/M_Brick_Clay_Old"
  parent_class: Material
  flags: {...}
  expressions: [...]           # generated by extract_material.py
  connections: [...]
  outputs: [...]
provenance: "<your-project>"
quality:
  compile: ok                  # or "failed"
  roundtrip: ok                # or "failed"
mi_compatible: false           # true if achievable as a MaterialInstance of
                               # /Game/Materials/M_PBR_Parameterized
```

`status` semantics:

- `ok` - good to suggest in retrieval
- `needs_review` - newly extracted, untagged or AI-proposed-only
- `bad` - flagged broken or unsuitable; excluded from retrieval
- `deprecated` - retired; excluded from retrieval
- `broken` - source asset no longer resolves; auto-set on index refresh

## Vocabulary

See the in-project `MaterialCatalog/vocabulary.md` for the active tag/trait vocabulary. Add new traits there when curating - don't under-tag.
